# 五、风险与边界

> 先把话说清楚：这套方案**不适合生产**，也不适合给别人提供托管服务。
> 它适合个人单机、给自己的 Agent 接一个能收发的 IM。

## 1. 合规与服务条款

- 自动化操作、非官方客户端接入通常**违反腾讯的服务条款**，存在**账号被封**的风险；
- 本仓库**不包含**任何密钥提取工具，也不指导绕过客户端保护；只讲"已有本地库和密钥时，怎么正确读取与发送"；
- 各国法律对"本地数据读取"和"绕过技术措施"的界定不同。**发布或使用前请自行确认当地法规**。

## 2. 数据安全

如果你要发布自己的实现，务必先清掉：

- [ ] 自己和其他人的 QQ 号 / uid / 群号
- [ ] 本地库密钥、登录令牌（`token`）
- [ ] 会话快照、inbox 记录、日志里的聊天原文
- [ ] 你的 persona 提示词（可能含个人偏好、内部信息）
- [ ] 路径里的用户名、机器名

建议：`.gitignore` 里排掉 `data/`、`*.db`、`*.log`、`config.local.*`，只在示例里用占位符。

## 3. 安全软件

- 驱动输入（xdotool）、adb、脚本自启常被杀软 HIPS 告警；
- 反复被杀软拦截时不要盲目加白，先确认拦截的是哪个可执行文件、哪类行为（文件 / 注册表 / 命令行调用）；
- 不要为了"能跑"去关闭实时防护。

## 4. 稳定性边界

| 风险 | 说明 | 缓解 |
|---|---|---|
| 客户端改版 | 表结构或输入框位置变化 → 读或发失效 | 版本探测 + 明确的失败告警，不要静默 |
| 窗口布局变化 | 群资料面板打开时输入框左移 | 坐标参数化 + 发送前区域校验 |
| 大量消息爆发 | 固定窗口（200 条）会丢消息 | 时间戳增量查询 |
| 客户端重启 | 可能停在登录页，发送全部落空 | 启动后自动登录 + 发送回读校验 |
| 磁盘空间 | 库会持续增长 | 定期清理/归档，别把整库复制到小分区 |

## 5. 已知的正确性陷阱（都是实测踩过的）

1. **UI 回执会骗人**：输入框变空 ≠ 消息发出，必须回读库；
2. **WAL 名字不配套**：剥头后另存的库，WAL 必须同名，否则读到旧数据；
3. **`@全体` 被当成 `@我`**：库里两者都进 `group_at_me_msg`；
4. **去重键不含消息 id**：连发两条相同文字会丢第二条；
5. **fail-closed 没自愈**：一次"结果未知"会永久堵死所有发送；
6. **`xdotool type` 发中文**：全部变 `?`，必须剪贴板。

## 6. 明确不做的

- 不做协议登录 / 不做扫码托管；
- 不提供密钥提取；
- 不做群发、私信轰炸、自动加好友；
- 不做"多账号养号"。

## 7. 如果你只是想学"怎么和 LLM 接 IM"

更省心的路线是：用官方支持的开放平台（QQ 官方机器人、Discord、Telegram Bot API）。
本文的价值在"当没有官方 API、又不想碰协议"时，还有这么一条路可以走。
